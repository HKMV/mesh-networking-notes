# Mesh VPN 实践笔记

> 私有组网（Mesh VPN）的选型与落地记录。Tailscale、ZeroTier、NetBird、EasyTier、vnt 都实际部署过，
> 当前 **主用 EasyTier（中继自建）+ NetBird 备用**，两套网络双开并存，需要时手动切优先级。

## 为什么是这个组合

- **EasyTier 做主用**：中继节点自己搭，虚拟网的流量和转发链路都不经过第三方；不依赖外部控制面，中继挂了也能直接连通的节点照旧能直连。
- **NetBird 做备用**：它是完全独立的一套（控制面、中继、客户端都另起），跟 EasyTier 不共用故障域。EasyTier 那套出问题时，备用链路大概率还活着。
- **双开并存 + 手动切优先级**：不做自动故障转移。自动切换最容易出的状态是「以为切了、其实没切」，排障时先怀疑自己；手动切虽然要动手，但每一步都是可确认的。

## 选型时我在意的判据

| 判据 | 为什么它决定了选型 |
|---|---|
| NAT 穿透成功率 | 决定平时是直连还是在走中继。走中继是带宽和延迟两个世界，穿透能力不行的话前面所有优点都白搭 |
| 中继是否自己可控 | 中继在别人机器上，等于把内网流量和可用性都交出去，高峰期被限速也无从解决 |
| 是否依赖中心控制面 | 有控制面省心，但控制面一挂或连不上，网络就起不来；去中心化的方案没有这个单点 |
| 多平台部署成本 | Windows / Arch Linux / macOS / 路由器，四类设备都得能装。少一类就是盲区，盲区里的设备等于不在网里 |
| 双栈与子网路由 | IPv4 / IPv6 都要能用；能不能把路由器后面的整个网段带进虚拟网，决定「加一台设备」是改一处还是改一片 |
| 许可证与可持续性 | 开源程度决定能不能长期依赖；闭源组件出问题只能等官方 |
