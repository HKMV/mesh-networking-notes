# Mesh VPN 实践笔记

> 私有组网（Mesh VPN）的选型与落地记录。Tailscale、ZeroTier、NetBird、EasyTier、vnt 都实际部署过，
> 当前 **主用 EasyTier（中继自建）+ NetBird 备用**，两套网络双开并存，需要时手动切优先级。

## 取材原则

- **每一条技术事实都来自官方文档或官方仓库**，出处在 [docs/sources.md](docs/sources.md)。
- 官方没写清楚的，文中写 `未确认`，**不拿印象补** —— 一份"看起来完整但有几格是猜的"对比表，比缺这几格更危险。
- 涉及许可的地方以仓库 `LICENSE` 原文为准，因为官方文档页脚、README 与 LICENSE 之间存在过互相矛盾的情况（下面点了名）。
- 抓取时间 **2026-11**，产品迭代快，引用前请自己复核。

## 为什么是这个组合

- **EasyTier 做主用**：中继（官方术语「共享节点」）自己搭，而且官方设计上**不需要中心控制面** —— 少一个会挂的东西，也少一处要长期运维的服务。
- **NetBird 做备用**：它自带 Management / Signal / Relay 一整套组件，跟 EasyTier 那头不共用任何故障域。代价是多维护一份，所以只当备用，不跑日常流量。
- **双开并存 + 手动切优先级**：不做自动故障转移。自动切换最容易出的状态是「以为切了、其实没切」，排障时先怀疑自己；手动切每一步都可确认。

## 选型时我在意的判据

| 判据 | 为什么它决定了选型 |
|---|---|
| NAT 穿透成功率 | 决定平时是直连还是在走中继。走中继是带宽和延迟两个世界，穿透不行的话前面所有优点都白搭 |
| 中继是否自己可控 | 中继在别人机器上，等于把内网流量和可用性一起交出去 |
| 是否依赖中心控制面 | 有控制面省心，但控制面一挂或连不上，网络就起不来；去中心化方案没这个单点 |
| 多平台部署成本 | Windows / Arch Linux / macOS / 路由器，四类设备都得能装。少一类就是盲区 |
| 双栈与子网路由 | IPv4 / IPv6 都要能用；能不能把路由器后面的整个网段带进虚拟网 |
| 许可证与可持续性 | 开源程度决定能不能长期依赖。这一条最容易被忽略，实际差异也最大（见对比表许可那行） |
