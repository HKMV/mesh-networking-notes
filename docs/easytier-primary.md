# 主用链路：EasyTier + 自建中继

> 主用链路的核心是「中继自己搭」。虚拟网的数据面自己掌控，可用性和带宽才不取决于别人。
> 具体的地址、网络名、密钥不公开，下面的要点按自己的环境替换参数。

## 角色划分

```
   公网可达                     内网 / 移动
┌──────────────┐          ┌───────────────┐   ┌───────────────┐
│  自建中继节点  │◄────────►│ 客户端 A（公司）│◄─►│ 客户端 B（家里）│
│  (VPS，公网 IP)│          │   Windows     │   │   Arch Linux  │
└──────────────┘          └───────────────┘   └───────────────┘
        ▲                         直连（能穿透时）
        └──────── 客户端 C（macOS / 路由器）────────┘
```

- **中继节点**：放在公网可达的机器上，唯一目标是「谁都连得上它」。它不承载业务。
- **客户端节点**：内网机器、笔记本、路由器。能直连时走直连，穿透失败时才落到中继上。
- 关键点：中继是**兜底**，不是**主路径**。判断标准是直连比例，不是「能连上就算成功」。

## 中继节点的部署要点

| 要点 | 说明 |
|---|---|
| 端口与协议 | UDP 和 TCP 都要放行，只留一个协议会在某些网络下直接连不上；端口在安全组和本机防火墙两处都要开 |
| 开机自启 | 用 systemd 或容器 restart 策略托管，机器重启后必须自己回来；手动 `nohup` 起的，早晚会在某次重启后静默消失 |
| 只允许自己的网络转发 | 中继要限制可转发的网络（白名单），否则一台公网中继等于给别人做免费中转 |
| 日志与轮转 | 至少保留进程日志和连接日志。排查「为什么走中继了」时只能靠连接日志，出问题再去开日志就晚了 |
| 监控 | 进程存活 + 端口可连 + 至少一个 peer 在线，三项都要有；只看进程存活会漏掉「进程在、转发不通」 |
| 资源 | 中继吃的是带宽不是 CPU，但连接数多时注意文件描述符上限和 UDP 缓冲区 |

## 客户端侧

- **多平台一致性**：Windows / Arch Linux / macOS / 路由器各按自己习惯的方式托管（服务、systemd、容器），但网络名、密钥、中继地址必须来自同一份配置来源，别手工抄。
- **启动顺序**：先确认中继可达，再起客户端。客户端先起、中继后起时，容易出现「看着在线、实际没连上中继」的假象。
- **路由器/网关**：用它把整个内网网段带进虚拟网，比在每台机器上装客户端省事；代价是这台路由器成为该网段的单点。
- **双栈**：IPv4 和 IPv6 各自验证一遍，很多「能连但打不开」是只通了其中一族。

## 出问题时的排查顺序

按这个顺序走，别跳步，每一步都拿到明确结论再进下一步：

1. **本机进程**：客户端进程在跑吗，日志最后一条是什么。
2. **到中继的连通性**：从中继的反方向也测一遍（从中继 ping/连客户端所在网络），单向通是最常见的坑。
3. **虚拟 IP 层**：虚拟网内的 IP 能不能通，通不了看是否拿到了虚拟 IP、是否在同一网络名/密钥下。
4. **跨子网**：虚拟 IP 通了但业务不通，检查子网路由有没有下发给对端、目标网段是否和对端本地网段冲突。
5. **实际路径**：确认这次是直连还是走中继 —— 「能通」和「通得快」是两件事。
